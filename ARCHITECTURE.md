## Schema

Four parallel "collection module" triplets (parent + images + valuations) plus shared users/auth, pursuit, Bearer-auth, and marketplace tables. All data tables are `user_id`-scoped.

```
users(id PK, email UNIQUE, name, image, password_hash, email_verified,
      last_login_at, listing_footer_default, created_at, updated_at)
accounts(id PK, user_id FK→users, type, provider, provider_account_id, UNIQUE(provider, provider_account_id), …)
user_modules(user_id FK, module IN('guitars','watches','automobiles','collectibles'),
             enabled, PK(user_id, module))

-- One triplet per module — only column shape differs:
{module}_items(id PK, user_id FK, category CHECK(...), brand, model, year,
               condition CHECK(...), purchase_price NUMERIC, …,
               insure BOOL NOT NULL DEFAULT FALSE, insurance_value,        -- 016
               insurance_value_source, insurance_value_date, archived_at,  -- 016
               specs JSONB, specs_updated_at,                              -- 019
               listing_intro,                                              -- 022
               listing_footer,                                             -- 023
               package_weight_lb, package_length_in,                       -- 024
               package_width_in, package_height_in,                        -- 024
               listing_price,                                              -- 025
               created_at, updated_at)
{module}_images(id PK, {module}_id FK→{module}_items,
                filename, path, mime_type, size, is_primary, sort_order, created_at,
                moderation_status TEXT CHECK(...), nsfw_score NUMERIC(5,4),
                nsfw_categories JSONB)                  -- migration 017
{module}_valuations(id PK, {module}_id FK,
                    valuation_type CHECK('ai','user'), price NUMERIC,
                    notes, comparable_sales JSONB, created_at)

-- Pursuits (saved searches) — one table per module, plus shared findings table:
{module}_pursuits(id PK, user_id FK, …, status CHECK('active','found','paused'), …)
pursuit_findings(id PK, pursuit_type CHECK(...), pursuit_id, source, title, url,
                 price, …, first_seen_at, last_seen_at,
                 UNIQUE(pursuit_type, pursuit_id, url))

-- Insurance + paperwork (migration 016 / CUR-2):
insurance_valuation_norms(module TEXT, category TEXT, multiplier NUMERIC,
                          notes, updated_at, PK(module, category))
paperwork_generations(id PK, user_id FK, kind CHECK('insurance'),
                      generated_at, item_count, total_insured_value, pdf_path)

-- Bearer-auth refresh tokens (migration 018):
refresh_tokens(id PK, user_id FK, token_hash UNIQUE,  -- SHA-256, never raw
               client, user_agent, ip, issued_at, expires_at,
               last_used_at, revoked_at, replaced_by FK→refresh_tokens)

-- Marketplace listings (migrations 020/021/024 — CUR-1 flip/sell):
marketplace_credentials(id PK, user_id FK, channel CHECK('reverb','ebay'),
                        token_encrypted, refresh_token_encrypted,   -- AES-256-GCM

marketplace_listings(id PK, user_id FK, channel CHECK('reverb','ebay'),
```

Image FK columns diverge by module (`guitar_item_id`, `watch_item_id`, `auto_id`, `iod_id`) — captured in `CollectionConfig.imageFkColumn`. `specs` is an ordered JSONB array of `{ label, value, source: "ai" | "manual" }`; AI regeneration replaces only `source='ai'` rows.

**Migrations:** `db/migrations/*.sql` (001–025) — tracked in `schema_migrations` by filename. Applied transactionally on container boot via `scripts/migrate.js` (Dockerfile CMD: `node scripts/migrate.js && exec node server.js`).

## Auth

- **Browser strategy:** NextAuth v4, JWT session (`session.strategy: "jwt"`). No DB session table. Cookie carries signed JWT containing `userId`. Source: `lib/auth.ts`.
- **Native-client strategy (PRs #48/#52/#53, migration 018):** `POST /api/auth/token` / `social` / `refresh` issue a 15-minute HS256 access JWT (`jose`, signed with `NEXTAUTH_SECRET`, claims `iss: vault1-api` / `aud: vault1-client`) plus a 30-day opaque refresh (`<row-id>.<secret>`; SHA-256 hash stored in `refresh_tokens`; rotation chain via `replaced_by`; replay of a revoked token revokes the chain). `lib/api-tokens.ts` signs/verifies; `lib/social-verify.ts` validates Apple/Google ID tokens against provider JWKS.
- **Resolver split:** migrated routes call `getApiSession(request)` (`lib/api-auth.ts`, Bearer OR cookie); CSV import, `value-batch`, pursuits, paperwork, data export/import, and admin remain cookie-only `getServerSession` until the iOS app needs them.
- **`last_login_at`:** Best-effort stamp on every successful Credentials `authorize()` and OAuth `signIn()` (`lib/auth.ts`). Used by `/api/mgmt/v1/summary` for "active in last 30 days".
- **Authorization model:** Ownership-based — every collection-data query filters `WHERE user_id = $session.user.id`. Admin endpoints gated by `isAdmin(session)` from `lib/admin.ts` (reads `ADMIN_EMAILS`); `session.user.isAdmin` stamped on the JWT for client nav gating; the API re-checks server-side. Mgmt API uses a separate app-wide bearer token. Known exception: the legacy autos/iod `images*` routes have no handler-level auth (TDD §9).
- **Roles:** Anonymous · Authenticated user · Authenticated admin (`ADMIN_EMAILS` allowlist) · Native client (Bearer; `getApiSession` surfaces only) · Cron container (`Bearer $CRON_SECRET`) · Mgmt-API caller (`Bearer $MGMT_API_TOKEN`) · eBay notification caller (verification-token challenge hash).
- **Middleware:** `middleware.ts` is a custom gate (PR #52 replaced `withAuth`): Bearer-carrying requests pass through to handler-level auth; otherwise a NextAuth cookie is required (API → 401 JSON, pages → 302 `/login`). Excluded: `login`, `register`, `privacy`, `api/auth`, `api/status`, `api/aasa`, `.well-known`, `api/pursuits/run-search`, `api/mgmt`, `api/marketplace/ebay/account-deletion`, `api/upload`, `api/data/import`, `_next/static`, `_next/image`, `favicon.ico`, `uploads`.

## Deployment

- **Production:** [`https://vault1.co`](https://vault1.co) (legacy `https://curatada-production.up.railway.app` still resolves; `NEXTAUTH_URL` should pin to the brand domain) — Railway service auto-built from `main` branch via the repo `Dockerfile` (multi-stage: deps → builder → runner). Container CMD runs migrations then execs the Next server. Postgres via Railway's Postgres plugin.
- **Staging:** a Railway `staging` environment in project VLT (`vault1-staging.up.railway.app`), deploying `main`, with its own Postgres. Since 2026-09-13 (VLT-36) it has its own `NEXTAUTH_SECRET` and `MGMT_API_TOKEN` (a session signed there is not valid on production), carries no `R2_*` or `EBAY_*` variables (photo upload and eBay do not work there by design), and sets `DEPLOY_ENV=staging` plus `VERIFIER_SECRET` for the verifier door, `POST /api/verifier/session`, which refuses in production whatever secret is presented. Production sets neither. A `staging` git branch also exists (created 2026-08-13; CUR-28).
- **Local dev:** `docker compose up -d db` + `npm run dev` against `.env.local`.
- **CI:** GitHub Actions workflows were removed in PR #70 per founder request (they had been added in PRs #49/#60). Railway's Docker build is the only automated gate; `tsc --noEmit` + `next build` remain the manual pre-PR discipline. PR #70 notes that branch protection's required `build` check must also be removed in GitHub Settings or `gh pr merge --auto` stalls. See TDD ADR-025.
- **Rollback:** Railway → Deployments → previous deploy → "Redeploy". No DB-level rollback; migrations are forward-only (016–025 are all additive).
